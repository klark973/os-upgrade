# Инструмент обновления ОС Альт

Пакет `os-upgrade` предназначен для полного обновления установленной ОС Альт,
а именно, для перехода с одного бранча (исходного) на следующий (целевой).
Обновление выполняется полностью автоматически без участия пользователя,
при этом учитываются все нюансы миграции на следующий бранч.

![01](/doc/01.png "Начало обновления программой os-upgrade")

## Системные требования

Окончательные системные требования зависят от поддерживаемого целевого
обновления из состава программы, таковые доступны в соответствующих
подкаталогах. Например, см. эталонную реализацию обновления Альт СП
релиз 10 ([c10f1](/doc/README-c10f1-ru.md)).

В любом случае подразумевается продуктовая ОС Альт. Нужно заблаговременно
позаботиться о свободном месте на диске – его должно быть не менее 25% до
запуска программы. По умолчанию до начала обновления запрашивается согласие
пользователя и проверяется доступность сетевого подключения. Подтверждение
можно отключить параметром `--force`. Для замкнутого контура с собственным
зеркалом (`--mirror=...`) проверку доступности сети тоже можно отключить
(`--ping=-`), либо можно указать другой адрес во внутренней сети для этой
проверки (`--ping=<hostname|hostaddr>`).

## Возможности os-upgrade

* автоматическое определение поддерживаемого целевого обновления;
* поддержка официальных публичных Интернет репозиториев ОС Альт;
* поддержка зеркал на подключаемом носителе или на локальном диске;
* поддержка зеркал в локальной сети, в том числе, для замкнутых контуров;
* поддержка защиты IMA/EVM: она отключается автоматически перед обновлением,
  а после обновления может быть включена обратно, даже в том случае, если
  ранее не была включена, это зависит от параметров запуска программы
  (по умолчанию обратно включается только в том случае, если была
  включена до начала обновления);
* поддержка фонового режима обновления с наименьшим числом перезагрузок
  (только для серверов без установленного графического рабочего стола);
* поддержка более безопасного обновления в изолированном таргете systemd
  (включена по умолчанию);
* расширенная диагностика и вывод деталей выполняемого обновления
  (включены по умолчанию, отключаются параметром `--quiet`);
* возможность указания непривилегированного пользователя, которому должен
  быть доступен процесс мониторинга обновления (параметром `--username=...`);
* возможность автоматического определения единственного непривилегированного
  пользователя, вошедшего в систему (параметром `--username=AUTO`);
* возможность подключения дополнительных источников APT (sources.list)
  в процессе обновления: выполняется после переключения на целевой бранч;
* по ходу обновления ведётся журнал `/var/log/os-upgrade.log`, он выводится
  на TTY11 (`Ctrl-Alt-F11`) и к нему можно интерактивно подключиться с любого
  терминала командой `os-upgrade --show`;
* поддерживается три режима цветности журнала и вывода в терминал: обычный,
  цветной и автоопределение (по умолчанию);
* программа самоудаляется после того, как выполнит обновление (по умолчанию,
  данный механизм отключается параметром `--keep-package`).

## Установка пакета

Пакет os-upgrade устанавливается командой `apt-repo test <номер таска>`,
где `<номер таска>` соответствует поддерживаемому целевому обновлению.
При этом он скачивается из «временного кармана», т.е. требуется доступ
в Интернет. Если программа ставится в замкнутом контуре без доступа во
внешнюю сеть, вместо `apt-repo test <номер таска>` можно использовать:

```bash
$ su-
# apt-get install /путь/к/os-upgrade-*.noarch.rpm
# os-upgrade --ping=- --mirror=<зеркало> [другие параметры...]
```

предварительно скачав пакет и разместив на локальном диске, где `<зеркало>` –
это начальный путь с исходным и целевым репозиториями в локальной файловой
системе (например, /ALT или file:/ALT), либо обычный FTP/HTTP URL локального
сервера с зеркалом (например, http://example.org/ALT). В качестве `<ping-host>`
можно также указать реальный IP-адрес либо имя хоста в локальной сети.
Если этого не сделать, то уже после запуска программы обновление начинается
автоматически с отправкой пингов на `ya.ru` и с использованием официального
зеркала ОС Альт. Скачать пакет заранее можно по адресу:

`https://git.altlinux.org/tasks/<номер таска>/build/<итерация>/<arch>/rpms/`,

где `<номер таска>` соответствует поддерживаемому целевому обновлению,
`<итерация>` является подкаталогом последней попытки сборки, обычно 100, 200,
300, и т.д., а `<arch>` – необходимая вам архитектура, например «x86_64» или
«aarch64». Посмотреть историю таска и выйти на скачивание в браузере можно
через адрес: `https://packages.altlinux.org/ru/tasks/<номер таска>/`.

## Запуск программы

После установки пакета доступна подсказка на русском и английском языке, в
зависимости от текущей локали: `os-upgrade --help`. Для систем, защищённых
механизмом IMA/EVM, запустить `os-upgrade` непосредственно сразу после
установки пакета не получится, для них предусмотрен второй вариант запуска:
`/bin/bash /usr/bin/os-upgrade --help`.

Для выполнения обновления сделайте резервные копии ценных данных и настроек
системы, временно отключите службы, которые не должны запускаться во время
обновления, в графической среде закройте все не нужные приложения, после
чего запустите в терминале:

```bash
$ su-
# os-upgrade [необходимые параметры...]
```

Зразу после запуска программы можно успеть выйти из графического сеанса,
чтобы ничего не мешало процессу обновления, и чтобы мониторить происходящее
на выделенном для этого терминале. В самом начале обновления программа
переключит активный терминал на TTY11, при этом она сама запустит одноимённый
сервис, а ближе к окончанию работы переключит активный терминал обратно на
TTY1. В течении всего обновления компьютер может быть недоступен даже снаружи
по сети и может быть перезагружен несколько раз.

## Удаление файлов и перезапуск обновления

Если что-то пошло не так на самом раннем этапе, смотрите вывод программы.
После устранения этих проблем утилиту можно попробовать запустить заново,
но сначала придётся удалить ранее созданные ей файлы и каталоги:

```bash
$ su-
# rm -f /etc/systemd/system/os-upgrade*
# rm -rf /var/lib/os-upgade /usr/local/libexec/os-upgrade
# os-upgrade [необходимые параметры...]
```

После частичного выполненного обновления это уже, скорее всего, не поможет.
Обратите внимание: никакие другие файлы пакета удалять вручную не следует!

## Мониторинг и просмотр результатов обновления

Пока пакет не удалён из системы, можно мониторить происходящее обновление,
в том числе, со стороны обычного пользователя, которому это было разрешено:
`os-upgrade --show`. При успешном обновлении без параметра `--keep-package`,
пакет os-upgrade самоудаляется и после окончания обновления в системе от
него останется только журнал обновления, который можно посмотреть командой:
`less -R /var/log/os-upgrade.log` (или чуть сложнее, если с первым способом
что-то не так: `cat /var/log/os-upgrade.log |less -r`).

## Источники APT и стороннее ПО

В начале обновления все сторонние источники APT отключаются, подключается
только официальное зеркало исходного бранча. То же самое происходит и при
обновлении индексов из целевого репозитория, но в этом случае можно заранее
подготовить файл со списком дополнительных источников и указать к нему путь.
Если этого не сделать, то уже установленное в системе стороннее ПО не
обновится, что может повлечь конфликт зависимостей. Как вариант, стороннее
ПО может оказаться несовместимо с библиотеками из целевого бранча. Так что,
если требуется учитывать стороннее ПО, обязательно используйте ключ `--apt=`.

## Ограничения и предостережения

Обратите внимание: программа не предназначена для обновления систем с
поломанной пакетной базой, неразрешёнными циклическими зависимостями сервисов
systemd или проблемами переключения между графическими режимами (modesetting).
Программа требует наличия определённых предустановленных пакетов, характерных
для официально выпущенных продуктов ОС Альт. Вы не сможете обновлять с её
помощью стартеркиты или регулярки на основе SysV init, равно как и другие
не продуктовые сборки.

В случае неисправимых проблем в процессе обновления, например, при временной
потере связи с публичным зеркалом, система может оказаться в недообновлённом
или в полностью неисправном состоянии. Поэтому заблаговременно позаботьтесь
о качественном Интернет соединении, свободном месте на диске, бесперебойном
питании от электросети и резервной копии своей системы.

Хотя программа стремится минимизировать ваши риски, успех обновления не
гарантирован. При возникновении проблем, журнал обновления может пригодиться
для восстановления работоспособности системы и разбора инцидента, в том числе,
вашей технической поддержке, но только в том случае, если при обновлении не
использовался параметр `--quiet`.
